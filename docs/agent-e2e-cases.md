# Agent 应用场景与端到端测试

测试分为真实公网 API、Android 虚拟机 UI、隔离故障测试三个层次。真实测试使用
Gateway 配置的 MiniMax-M3 和 ai-server 的 ComfyUI；故障测试使用真实 Gateway
HTTP 路由，但替换模型与 ComfyUI 适配器以确定性注入错误。两者的结果分别统计。

## 真实 Gateway + 模型 + ComfyUI

自动化入口：`tests/e2e/agent-live.test.mjs`。

| 场景 | 用户行为与断言 |
|---|---|
| 访问与配置 | 未登录拒绝访问；已配置模型可用；响应不含 setup token |
| 导入已有工作流 | 创建独立 v1，完整保留 canvas；拒绝不支持的版本、bypass 和未知节点 |
| 理解工作流 | 解释 LoadImage/SaveImage，不修改版本、不执行 |
| 修改但不生成 | 修改输出路径、校验、保存 v2，v1 不变 |
| 多轮对话 | 下一轮沿用修改后的参数，真实预览一次，64×64 图片可解码 |
| 撤销修改 | 恢复 v1 为 v3，历史 v2 保持不变；旧 baseVersion 返回 409 |
| 无效输入诊断 | 导入不存在的图片，只诊断；后续提供有效文件名后修复、保存 |
| 重复提交 | 相同 requestId、消息和附件返回同一任务；更换消息或附件冲突 |
| 附件消息 | 输入框上传图片/视频/音频到 ComfyUI input 目录后随消息发送；纯附件消息可发送；文件名穿越、output 类型、超过 8 个返回 400；模型收到附件的 loader 路径和像素尺寸/横竖方向（App 上传时本地读取，宽高必须成对，0 或缺一返回 400），并被要求在接线前检查参考图是否匹配目标；AGENT_LLM_VISION 开启时可读的 PNG/JPEG/WebP/GIF 同时作为图片输入发给模型，视频和读取失败的文件只保留路径，图片不写入任务消息 |
| 并发操作 | 同会话已有任务时拒绝第二条消息和版本恢复 |
| 取消与继续 | 取消可重复调用，重复提交不重跑；新 requestId 可以继续 |
| 参数校验 | 空消息（无附件）、过长消息、无效 UUID、伪造 owner、负游标不产生任务 |
| 离线恢复数据 | 205 个事件分两页读取，无缺失或重复；末尾游标返回空集 |
| 会话权限 | 另一设备无法列出、读取、保存、恢复、发消息或取消管理员会话 |
| 从空白创建 | 读取真实环境；没有 checkpoint 时说明缺失，不编造模型、不运行 |

这些断言组合成 13 个子测试；Node 测试统计包含外层父测试，因此显示 14/14。
每轮上传程序生成的 64×64 色块，唯一输出前缀为 `ComfyMobileE2E/AgentCases/<UUID>`。
测试会话和输出保留作审计，收尾取消本轮仍活动的任务并吊销本轮注册的设备。

## Android 虚拟机 UI

在原有 20 项 Android 用例上启用 `E2E_AGENT_LIVE=1`，增加一个包含下列连续用户操作
的 Agent 场景。入口：`tests/e2e/agent-android-scenario.mjs`。

1. 从本地工作流库导入助手副本，通过输入框提交自然语言指令。
2. 模型修改、执行一次、保存 v2；真实结果图片加载，页面没有横向溢出。
3. App force-stop 后重启，恢复设备凭据、会话及保存版本。
4. 空消息禁用发送；任务进行中禁用第二次发送。
5. 多轮修改并保存 v3，不要求生成时不重复执行。
6. 模型工作时离开页面再返回，恢复后台任务和结果。
7. 点击版本历史的恢复按钮，将 v1 恢复为 v4。
8. 点击停止助手；任务停止后发送新消息并正常得到回复。
9. 新建空白会话，确认不混入旧对话，再切回原会话。
10. 检查上述操作后仍只有一次 ComfyUI 执行；打开工作流副本进入编辑器。

测试仅允许 `emulator-*` 且 `ro.kernel.qemu=1`，当前使用 `emulator-5554`。
所有 ADB 命令指定该 serial；收尾仅清空调试包与吊销本轮新增设备凭据。

## 隔离故障与运行时回归

入口：`npm run test:agent`，包含工作流引擎、Agent 编排及真实 HTTP 路由。

- 模型认证/网络错误：客户端收到可理解的错误，不泄漏内部错误详情，不自动重试。
- 模型恢复：同一会话的新消息可以继续，已保存工作流仍在。
- 模型空回复：任务明确失败，不误报完成。
- ComfyUI 不可达：明确失败，不调用模型，不改已有工作流。
- 达到耗时上限：停止任务，不继续调用模型。
- 未配置模型：可以导入与保存，发送消息返回 503。
- ComfyUI 执行失败：模型接收执行诊断，修复后在预算内重试。
- 提交回包丢失：通过队列/历史找回执行，不重复 POST；无法确认时明确停止。
- Gateway 重启：恢复进行中的执行并保留原工作流版本，不重复提交。
- 调用次数/预览次数限制、取消 GPU 等待、原子 patch、输入范围、循环连接及不支持节点等回归。

不通过中断生产模型服务、ComfyUI 或 Gateway 来制造故障。

  npm run test:e2e:agent

E2E_AGENT_LIVE=1 EMULATOR_SERIAL=emulator-5554 \

npm run test:gateway

### 重复运行发现并处理的问题

真实 API 第二轮在“随后预览一次”上失败：模型仅回复“好的，使用版本 2 提交预览。”，
没有 tool call，旧逻辑直接把任务标为 completed。失败报告保留在
`tests/output/agent-cases/3462890d-120d-4ebd-b0bb-4d1b82c59ab5/report.json`。

现在首次得到纯文本最终答复时，会先结合当前任务与工具结果做一次完成复核，
候选答复不立即展示为最终结果；复核使用 required 工具选择，未完成时调用操作工具，
已完成或受阻时调用 finish_response。若 provider 忽略工具要求，任务明确失败。
每个任务最多复核一次，
标记持久化到 SQLite，复核消耗现有模型调用次数预算，并可能增加一次模型请求。
系统提示也明确最新一轮的执行授权优先于之前一轮的“不运行”。
新增确定性回归验证“口头承诺 → 复核 → 真正执行一次 → 完成”，Agent 测试变为 27/27（含 provider 忽略 required 的失败保护）。
该复核改善模型行为，但不是对任意模型输出的形式化保证，仍需保留真实场景回归。

Android 首轮还发现脚本提前点击了禁用中的停止按钮；已改为等待按钮可用。
失败时保留页面文本和截图。修正同步后，扩展的 Android 21/21 已通过。

进一步复测发现 MiniMax 在复核继承完整对话时，可能忽略 required，触发
`AI_ToolChoiceViolationError`，尤其是在用户要求“不调用工具”的纯文字回复中。
复核现使用独立的审查上下文，将原始请求、当前工作流、实际工具结果和候选答复
作为数据提供，区分工作流操作与内部的最终答复格式化。失败日志仅记录任务 ID、
异常类别和代码位置，不记录 provider 消息、响应体或凭据。

最终部署版本复测：真实 API 13/13 场景通过（Node 统计 14/14）；Android 全套 21/21
通过，包含修复执行、后台恢复、v1→v4 恢复、取消后继续、会话切换和打开画布。
Agent/工作流/隔离故障回归 27/27 通过。服务器容器健康，`.env` 校验未变化，
测试新增设备凭据已清理。当前 Android 报告为 `tests/output/agent-android/report.json`。
