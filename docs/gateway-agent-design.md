# Gateway ComfyUI Agent 设计

状态：MVP 已实现；模拟联调和 MiniMax-M3 + 真实 ComfyUI 图片复制联调通过，文生图待兼容 checkpoint 验收。日期：2026-09-05。

实施进展：`gateway/workflow/` 已接入 `gateway/agent/`（Vercel AI SDK、SQLite、后台任务和认证路由），App 新增 `/agent` 入口、会话/版本/结果卡片。MVP 用轮询等待执行和补取事件；默认关闭，通过环境变量启用。真实 MiniMax-M3 已完成错误文件名修复、校验、ComfyUI 执行和保存；返回图片已核对为 64×64 PNG。该验证不包含扩散模型推理，当前实例没有基础模板所需的 checkpoint。具体配置、身份边界和限制见 `gateway/agent/README.md`。不支持画布节点增删、任意自定义节点和图像理解。下文保留原始设计方向，非全部已实现。

## 已确定的方向

- 产品目标：用户通过自然语言生成、修改、试跑、修复和保存 workflow，不必先掌握节点连接。
- Agent 在 Gateway 服务端运行；App 负责聊天、展示改动、进度与结果，以及停止任务。
- 使用 Vercel AI SDK（核心包 `ai`）接入模型与工具调用循环。具体模型及依赖版本在实施时验证确定。
- Agent 自主选择操作步骤；程序负责参数、工作流、版本、执行预算和任务归属校验。
- 首版围绕已安装模型和节点、经过验证的模板，完成文生图闭环，并支持解释和修改已有工作流。

以下模块、接口名和状态为实施建议，不表示现有系统已经具备这些能力。

## 首版边界

支持环境查询、模板选择、批量工作流修改、校验、预览执行、结构化错误诊断、有限次数自动修复、版本保存与回退。

首次适配明确的一组节点和模板。对于暂不支持的自定义节点、动态输入、子图或虚拟节点，返回明确的兼容性诊断，不静默丢弃数据。执行成功与视觉满意分别处理；结果展示后允许用户继续反馈。

自动安装插件、修改 Python 环境、编写自定义节点、任意 shell 执行、多 agent 协作和视频生成不进入首版。图像理解取决于选定模型和图片传输能力，须单独验证。

## 模块边界

| 模块 | 责任 |
| --- | --- |
| App | 聊天、结果与工作流改动卡片、停止、重连补取事件 |
| Gateway API | 沿用认证体系，校验会话与任务归属，创建任务和读取事件 |
| 后台执行器 | 调度任务、状态转换、预算、取消和重启恢复 |
| Agent Runtime | 使用 AI SDK 调用模型，根据工具结果决定下一步 |
| Comfy 工具层 | 为 agent 暴露有类型、可审计的业务操作 |
| Workflow Engine | 内部图表示、原子修改、校验、执行格式与编辑格式转换 |
| Comfy Adapter | 实例能力发现、HTTP 提交、WebSocket 事件、队列与历史查询 |
| 存储 | 会话、任务、版本、工具调用、执行记录和有序事件 |

建议新增模块使用 TypeScript。首版采用单实例 Gateway 与 SQLite；数据库驱动、构建方式和迁移工具在实施时确定。模块边界允许以后拆出独立 worker。数据库访问与网络调用不能阻塞 Gateway 代理请求。

## 工作流工具

| 建议工具 | 行为 |
| --- | --- |
| `inspect_environment` | 返回绑定实例的能力摘要 |
| `search_nodes` / `get_node_schema` | 搜索节点并按需获取参数、输入输出定义 |
| `list_models` | 获取实例实际可用的模型选项 |
| `search_templates` | 返回模板摘要和兼容条件，按需读取内容 |
| `get_workflow` | 读取工作流及版本 |
| `apply_workflow_patch` | 根据基础版本原子应用一组节点、连接和参数修改 |
| `validate_workflow` | 返回节点、参数、连线及兼容性诊断 |
| `submit_preview` / `get_run` | 提交预览，查询本任务的执行状态和结果 |
| `save_workflow_version` | 保存工作流版本及说明 |

工具输入用 Zod 等 schema 校验，业务层另行校验语义和授权范围。用户与实例标识由服务端上下文注入，不能信任模型传入的归属字段。

批量修改携带 `baseVersion`。先在副本上应用并校验，再整体写入新版本；版本冲突要求重新读取，不覆盖用户在画布上的新修改。改动记录支持差异展示与回退。

内部图表示必须保留画布编辑所需元数据，并能生成 ComfyUI 执行数据。复用现有转换逻辑前，先提取依赖浏览器或 React store 的部分。用往返转换验证参数、连接和布局保真；不承诺首版兼容任意 workflow。

本地校验不等同于执行验证；提交 ComfyUI 的 `/prompt` 在校验成功后会入队，不应当作为无副作用的预检查接口。

## 上下文与会话

每轮提供需求摘要、绑定实例、工作流版本、最近工具结果和已经尝试的修复。节点定义、模板正文、完整错误日志按需读取，不将整个节点库塞入每轮上下文。

完整记录保存到服务端，模型上下文可以使用摘要。截断日志需标记，并支持查询原文。记录用户明确表达的偏好；首版不依赖向量数据库。

## 后台任务与恢复

建议任务状态：`queued`、`running`、`waiting_comfy`、`waiting_user`、`reconciling`、`completed`、`failed`、`cancelled`。Agent 循环与业务任务状态分开管理。

1. 聊天请求创建任务后返回任务 ID；后台执行器驱动 agent。
2. 提交预览前保存提交意图、工作流版本及关联标识；提交成功后保存 ComfyUI prompt ID。
3. 执行期间进入 `waiting_comfy`，由后台监听或有限轮询等待，无需反复调用模型。
4. 完成或报错事件归档后，恢复 agent 进行展示或有限重试。
5. 重启后先核对队列和历史，再决定继续等待、处理结果或进入待处理状态。

提交请求与保存返回值无法保证跨系统原子性。若在“已提交但未保存 prompt ID”之间崩溃，先通过可用关联信息核对原任务；无法确认时保留不确定状态并提示用户，不盲目重新提交。会话恢复不等于外部执行的 exactly-once 保证。

同一会话首版串行修改。任务绑定用户、会话、ComfyUI 实例、工作流版本和执行记录。取消 agent 后不得继续发起新调用；已经运行的 GPU 任务需确认归属与实例取消能力，不能误中断其他用户的执行。

模型调用次数、修复次数、预览次数和任务耗时设可配置上限。具体默认值通过真实任务评估确定。

## 持久化与事件

建议实体：会话、消息、任务、工具调用、工作流版本、ComfyUI 执行记录、事件。保存关键状态转换与工具结果，而不只保存聊天文本。图片优先保存受认证访问的引用，避免将大文件直接写入聊天记录。

事件至少包含任务 ID、递增序号、类型、时间和结构化载荷。App 按最后接收序号补取并去重，断线不取消任务。实时传输沿用 WebSocket 或使用兼容原生认证的流式 HTTP，实施时验证 Android 的连接与重连行为。

任务数据按用户或设备授权模型隔离，复用现有 Gateway 认证。模型密钥保留服务端，不进入事件、日志和前端响应。

## App 交互

- 工作流改动卡片：改动摘要、查看差异、回退。
- 执行卡片：排队、运行、失败、停止。
- 结果卡片：输出预览、绑定版本、继续调整。
- 待补充信息卡片：缺失输入或需要用户决定时暂停。

每个结果绑定实际执行的不可变工作流版本，支持“回到第二张，只修改背景”。普通操作在用户请求范围内自动完成。

## 实施顺序与验收

1. **工作流基础层**：提取服务端可用的图操作与 Comfy Adapter；用样例验证修改、校验及编辑/执行格式一致性。
2. **任务存储与执行器**：实现状态、事件、版本冲突、取消与恢复；重点验证重启不会盲目重复提交。
3. **Agent 最小闭环**：接入 AI SDK、一个模型 provider、模板与工具；跑通自然语言生成、预览、报错修复和保存。
4. **App 入口**：聊天和四类卡片、断线补取、结果继续修改；验证手机退出后服务端任务继续。
5. **真实场景评估**：记录成功率、人工介入次数、模型耗时、GPU 耗时和调用成本，再扩展节点与场景。

关键验收案例：模板生成成功；已有工作流改参数；缺模型时准确诊断；连接或参数错误修复；达到重试上限停止；并发编辑发生版本冲突；App 重连不丢事件；Gateway 重启核对原任务；取消不影响其他任务；生成结果可在画布继续编辑。

## 实施前待定项

- 首个模型服务商、模型名称与图片输入支持。
- 已部署实例可用于验收的模型、节点和模板。
- AI SDK 与 Zod 的兼容版本、Node 运行版本、TypeScript 构建与 SQLite 驱动。
- 会话和现有设备认证的归属映射、任务保留期限、预算默认值。
