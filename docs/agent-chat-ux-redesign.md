# Agent Chat 入口与工作流结合重设计

状态：设计已确认，待实施。日期：2026-09-06。

## 背景与问题

0.3.0 里 Agent Chat 的入口是侧边菜单的一行"工作流助手"，跳到独立的 `/agent` 全屏页。现状问题：

- 入口藏在侧边菜单里，首页、编辑器、画廊都没有入口。
- `/agent` 页有自己的配色和控件，会话选择和"新会话起点"都是原生 `<select>`，与 App 其余页面不一致。
- Gateway 会话与本地工作流库是单向复制关系：创建会话只能"导入副本"，助手改完再"在画布打开副本"，本地库堆出 `xxx · v3`、`xxx · 助手副本` 这类文件。
- 从编辑器到助手要退出编辑器、开侧边菜单、进助手、新建、下拉选工作流。
- Gateway 会话版本、本地 `revision`、云同步 `etag` 三套版本并存，用户看不出关系。

## 已确定的方向

- 移动端画布可编辑性差，产品以**对话为主**，画布是辅助视图。
- 首页改为**底部标签栏**：对话 / 工作流 / 画廊，默认落"对话"。
- 会话与工作流**一对一绑定**：助手每提交一个版本就写进绑定的工作流，不再产生副本，用户不需要点"保存"。
- "对话"标签第一屏是**会话列表**；新对话直接进空聊天，起点由助手根据描述决定。
- 编辑器与聊天**双向跳转，不内嵌**。
- 没有 Gateway 或没配模型时"对话"标签常驻，显示引导。

## 1. 导航与信息架构

底部标签栏由一个共用外壳组件提供，只在三个顶层页面显示，各页面保留自己的头部。

| 标签 | 路由 | 内容 |
| --- | --- | --- |
| 对话 | `/chats` | 会话列表 |
| 工作流 | `/workflows` | 现有 WorkflowList，原样迁移 |
| 画廊 | `/outputs` | 现有 OutputsGallery |

- 侧边菜单删除"工作流助手"和"画廊"两行。
- 默认标签：首次启动时，助手可用（`authMode === 'gateway'` 且 `providerReady`）落"对话"，否则落"工作流"。之后记住用户上次停留的标签，存 localStorage。
- `/` 是入口重定向：读取上次停留的标签；没有记录时按助手可用性选择。被重定向到"工作流"的那次不会覆盖记住的标签。
- 全屏页面不显示标签栏：`/chat/:sessionId`、`/chat/new`、画布编辑器、设置等。编辑器的"返回"改为回到 `/workflows`。
- "对话"标签在助手不可用时显示引导页：未连接 Gateway 时说明需要 Gateway 并给"打开连接设置"；已连接但 `providerReady` 为假时说明"等待管理员配置语言模型"并给"重新检查"。
- 有会话处于活跃任务状态时，"对话"标签显示小圆点角标。
- 旧路由 `/agent` 保留到下一个次版本，重定向到 `/`。

## 2. 会话列表页

头部：菜单按钮、App 图标、标题"对话"、服务器芯片，右侧"新对话"按钮。样式沿用 WorkflowList 头部。

列表每行一个会话：

- 缩略图：绑定工作流的缩略图，其次最近一次生成结果的图，都没有则显示模型图标。
- 第一行：会话名，即绑定工作流的名字；未绑定时用第一条用户消息前几十字。
- 第二行：最后一条消息摘要，一行截断。
- 右侧：相对时间和状态角标。角标只有三种：生成中（转圈）、上轮出错（橙点）、无。
- 长按或左滑：删除会话。删除会话不删工作流，只解绑。

列表上方有搜索框，按会话名和摘要过滤。现有 AgentHistory 弹窗删除，其搜索逻辑迁移到列表页。

空状态：一段说明加三个建议芯片，与新对话页芯片相同，点击进入新对话并预填。

数据：`GET /sessions` 扩展返回最后一条消息、最后活动时间、是否有活跃任务、绑定工作流信息、缩略图引用。列表页在前台时每 5 秒轮询一次，只用于刷新状态角标；切到后台或离开页面停止。

## 3. 聊天页

头部：返回、标题（绑定工作流名，未绑定时"新对话"）、"画布"按钮打开绑定工作流、"更多"菜单（重命名、版本历史、删除会话）。删除现有的会话下拉框、"新会话起点"下拉框和底部"版本历史"折叠区。

新对话 `/chat/new`：

- 进入即空聊天，输入框上方三个芯片："生成一张图片"、"生成一段短视频"、"从我的工作流开始"。
- 前两个芯片把示例文案填入输入框；第三个弹底部面板选库里的工作流，选后标题变为该工作流名，并显示"已载入工作流 · N 个节点"卡片。
- `/chat/new?workflow=<id>` 直接进入已载入状态。
- 会话在第一条消息发送时才创建，创建请求带画布和绑定信息，成功后路由替换为 `/chat/:id`。

消息流沿用 AgentTranscript，卡片收敛为三种：

- 工作流改动卡：一句摘要、"查看改动"折叠、"在画布查看"按钮。去掉"保存"和"恢复"。
- 结果卡：媒体网格，可全屏预览，"保存到相册"复用 FilePreviewModal 的下载逻辑，底部小字标版本号。
- 出错卡：一句人话说明加"查看诊断"折叠。

版本：不要求用户点"保存"。助手每提交一个新版本，App 写入绑定工作流，工作流库和云同步自然跟上。"版本历史"从更多菜单进入，底部面板列出版本摘要和时间，每项一个"回到这个版本"按钮，调用现有 `restore` 产生新版本。

输入区：文本框加发送键。有任务在跑时输入区变为状态条（"ComfyUI 正在生成…"）加"停止"按钮。"离开页面后后台任务继续运行"只在第一次提交时 toast 一次。

滚动：保留"跟随最新"和"回到最新消息"行为。

## 4. 绑定机制

绑定数据：

- Gateway 会话增加 `workflow: { id, name, filename? }`。`id` 是 App 本地工作流 id，`filename` 是云同步文件名。会话名不再单独维护，取工作流名。
- 本地工作流增加 `agent: { sessionId, mirroredVersion, mirroredHash }` 字段。`mirroredVersion` 记录库里这份内容对应的会话版本号，`mirroredHash` 是镜像或导入时 `workflow_json` 的内容哈希（键排序后计算）。
- 解析顺序：先按 `id` 找，找不到按 `filename` 找（换设备后云端下载的工作流 id 不同），都找不到视为未绑定，聊天页提示"工作流已删除，可以从当前版本重新创建"。

助手 → 画布：聊天页每收到 `workflow` 事件，拉取该版本画布，写入绑定工作流的 `workflow_json`，更新 `mirroredVersion`，走现有 `updateWorkflow`，云同步照常标脏上传。会话尚未绑定时（从空白开始，助手第一次建出工作流），App 创建新本地工作流并通过 `PATCH /sessions/:id` 回写绑定。

画布 → 助手：用户在画布改动后回到聊天页，App 比较本地 `workflow_json` 的哈希与 `mirroredHash`（IndexedDB 每次写入都会覆盖 `modifiedAt`，所以不能用时间戳）。不一致则在发下一条消息前先调用 `POST /sessions/:id/versions` 把当前画布作为新版本提交，摘要"画布修改"，再发消息。Gateway 对不支持的画布返回 422，聊天页显示提示卡"画布里有助手暂不支持的改动，助手将基于上一版本继续"，用户确认后继续。

编辑器入口：WorkflowHeader 加"对话"按钮。工作流有绑定会话则跳转，否则进 `/chat/new?workflow=<id>`。工作流列表的长按菜单加"和助手对话"。

删除：删会话只清工作流上的 `agent` 字段；删工作流不删会话，会话变为未绑定，下次产生版本时重新建工作流。

并发：同一会话一次只跑一个任务，版本冲突沿用 `baseVersion` 409。

## 5. Gateway 接口

均在 `/api/gateway/agent` 下，沿用现有认证与归属校验。

| 接口 | 用途 |
| --- | --- |
| GET `/sessions` | 每项增加 `lastMessage`、`lastActivity`、`active`、`workflow`、`thumbnail` |
| POST `/sessions` | 请求体增加 `workflow` 绑定信息 |
| PATCH `/sessions/:id` | 改名、写入或清除 `workflow` 绑定 |
| DELETE `/sessions/:id` | 删除会话及其任务、版本、事件；有活跃任务先取消 |
| POST `/sessions/:id/versions` | 以当前画布创建新版本，带 `baseVersion` 和摘要 |

现有 `/save` 保留给模型工具，App 不再调用。

## 6. 错误处理

- 助手接口失败：聊天页顶部显示可重试横幅，不遮挡消息流；会话列表页显示带重试的空状态。
- 绑定工作流找不到：不报错，按第 4 节提示并允许重新创建。
- 画布镜像写入本地失败（配额等）：toast 提示，不影响对话继续。

## 7. 测试

- Gateway：新接口单元测试，覆盖绑定写入、删除级联、画布导入版本、422 不支持画布、跨 owner 访问被拒。
- 前端：绑定解析（id 优先、filename 回退）、镜像版本比较、默认标签选择，写成纯函数单测。
- E2E：`agent-android-scenario` 改走新路径：新对话 → 发消息 → 结果卡 → 画布查看 → 画布改参数 → 回聊天发消息时自动导入版本。

## 8. 迁移与边界

- 旧会话没有绑定信息，列表照常显示，打开后第一次产生新版本时自动建工作流并绑定。
- 不做：编辑器内嵌聊天、平板分栏、Agent 工具与模型逻辑改动、画廊改动。
